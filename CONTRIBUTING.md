# Contributing to GEISA Community

Community contributions are welcome.

This repository accepts software, applications, platform foundations, example
implementations, demonstrations, tools, documentation, and other open-source
resources relevant to GEISA implementations or operations.

## Pull Requests

All changes must be submitted through a GitHub pull request.

Bug fixes, documentation updates, and improvements to existing projects may be
submitted directly as pull requests without first opening an issue.

A pull request that adds a new Community project should include enough
information for reviewers to understand the contribution and determine where it
belongs in the repository.

## Adding a Community Project

A new project should include documentation that identifies:

- the project's purpose
- its relationship to GEISA
- the project maintainer or maintainers
- its current status
- its license if other than Apache 2.0 as the Community default
- supported or tested GEISA specification versions, where applicable
- basic build, installation, or usage instructions
- known limitations
- support and maintenance expectations

Suggested project status values are:

- Active
- Experimental
- Maintenance Limited
- Looking for Maintainer
- Retired

If a project does not fit the existing repository structure, describe the
project and proposed location in the pull request and the epository maintainers
will help to determine an appropriate location.

## Project Ownership

Each Community project should identify at least one maintainer.

Project maintainers are responsible for reviewing relevant contributions and
responding to project-specific questions and issue reports on a best-effort
basis.

Repository maintainers may help route questions and contributions but do not
automatically assume responsibility for individual Community projects.

## Licensing

Unless a project clearly identifies another open-source license, contributions
are licensed under the Apache License, Version 2.0, provided in the root of this
repository.

Projects using another open-source license must include the applicable license
text and clearly identify the license in their documentation.

This repository is not intended for closed-source submissions, proprietary
product listings, or marketing-only entries.

## GEISA Specification and Conformance Changes and Issues

Changes to or issues in the GEISA specification, schemas, or conformance
framework should be submitted to the appropriate GEISA repository rather
than to this repository.
