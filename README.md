# GEISA Community

The GEISA Community repository contains software, platform foundations,
applications, example implementations, demonstrations, tools, documentation,
and other resources related to the Grid Edge Interoperability and Security
Alliance (GEISA).

Its purpose is to encourage adoption of GEISA by providing a place where
developers, utilities, vendors, researchers, and other members of the community
can contribute and share projects that help implement, evaluate, or use GEISA.

Unlike the GEISA Specification and Conformance repositories, the contents of
this repository do not define the GEISA specification or determine GEISA
conformance.

## GEISA Ecosystem

The GEISA project is organized around three primary repositories:

| Repository    | Purpose                                                                |
|---------------|------------------------------------------------------------------------|
| Specification | Defines the GEISA specification, schemas, and documentation            |
| Conformance   | Provides the official GEISA conformance test framework                 |
| Community     | Community-developed software and supporting resources related to GEISA |

## Official GEISA Resources

For information about GEISA itself, please refer to the official project
resources.

- [LF Energy GEISA project](https://geisa.energy/)
- [Published GEISA specification](https://spec.geisa.energy/latest/index.html)
- [GEISA specification repository](https://github.com/geisa/specification)
- [GEISA conformance repository](https://github.com/geisa/conformance)
- [All GEISA repositories](https://github.com/orgs/geisa/repositories)

Questions regarding the GEISA specification, schemas, or conformance
requirements should be directed to the appropriate official repository rather
than the Community repository.

## Scope

Community projects may include, but are not limited to:

- Applications
- Platform foundations
- Example implementations
- Demonstrations
- SDKs
- Utilities and tools
- Integration projects
- Documentation
- Notes and other resources relevant to GEISA implementations or operations

If a proposed contribution does not naturally fit within the existing
repository structure, contributors are encouraged to describe the project in a
pull request so that an appropriate location can be determined.

Changes to the GEISA specification, schemas, or conformance framework belong in
their respective repositories.

## Relationship to GEISA Releases

Community projects are versioned independently from GEISA specification
releases.

Individual projects may support one or more versions of the GEISA specification
as documented by that project.

Projects in this repository may evolve independently of GEISA specification
releases.

## Repository Organization

As the repository grows, projects will generally be organized into categories
such as:

- Applications
- Platform Foundations
- Example Implementations
- Demonstrations
- Tools

Additional categories may be introduced as the Community grows over time.

## Contributing

Community contributions are welcome.

Contributions should be submitted as GitHub pull requests in this repository.

When contributing a new Community project, the initial pull request should
include sufficient information for reviewers to understand the project,
including:

- the purpose of the project
- its relationship to GEISA
- the proposed location within this repository
- the project's maintainer(s)
- project status (for example: Active, Experimental, Maintenance Limited,
  Looking for Maintainer, or Retired)
- applicable license
- supported or tested GEISA specification version(s), where appropriate
- basic build or usage instructions
- known limitations, if applicable

Each new Community project should clearly identify its maintainer(s), project
status, license, supported or tested GEISA versions where applicable, and known
limitations within its own documentation.

Questions, issue reports, and contributions are welcome. Responses are provided
on a best-effort basis by the relevant project maintainer(s).

Inclusion in this repository does not imply endorsement, certification,
recommendation, or support by the GEISA Working Group or LF Energy.

## Maintenance Expectations

Each Community project identifies its own maintainer(s). Repository maintainers
may help route questions and contributions, but they do not automatically
assume maintenance responsibility for individual Community projects.

Projects may be actively maintained, maintained on a best-effort basis, become
inactive, or eventually be retired.

Unless a project explicitly states otherwise:

- there is no guaranteed support
- there is no guaranteed maintenance
- there is no guaranteed compatibility with future GEISA releases
- there is no guaranteed security maintenance
- there is no defined release cadence
